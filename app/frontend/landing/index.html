    What makes it different

    Compared with the usual ways small apps get deployed

    This compares approaches, not products. "Tutorial-style" means a quick deploy on a public VM with a long-lived database password. "Console-driven" means clicking infrastructure into existence in a cloud console.

    Concern Tutorial-style Console-driven This project
    Database password One long-lived secret in an env file Set once by hand, rarely rotated Vault mints a new Postgres role per deploy, 1 h default TTL, 24 h max
    App host and the internet Open egress; installs from the public registry Open by default Security-group egress limited to the VPC CIDR; deps arrive as a prebuilt wheelhouse
    Secrets store restarts Not applicable Cloud KMS auto-unseal A second Vault cluster auto-unseals the first via Transit, no cloud KMS
    Repeatability A README of commands Screenshots of clicks Terraform for AWS, one Ansible role, a script per phase

    1. Credentials that expire on their own

      The app never holds a long-lived database password. The role is created with VALID UNTIL and joins a stable group role so table ownership survives rotation.

      infra/scripts/03-terraform-apply.sh

    2. A host that structurally cannot phone home

      The EC2 security group allows egress only to the VPC CIDR. RDS sits in private subnets with publicly_accessible = false.

      infra/terraform/main.tf

    3. Dependencies resolved ahead of time

      pip download targets the instance's platform; the host then runs a real pip install --no-index against that directory.

      infra/scripts/build-app.sh

    4. A demo that exercises the real flows

      One module, src/api/index.js, is the only thing the UI talks to. A build flag swaps HTTP for a simulator that mirrors the backend's routes, validation and status codes, covered by tests. The Activity page in the demo above shows it live.

      Open the demo's Activity page

    5. Bugs found by reading, fixed with tests

      While preparing this page: over-long names returned HTTP 500 on Postgres, % in search acted as a wildcard, the list endpoint was unbounded, and unknown /api paths returned the HTML shell with a 200. All four are fixed and tested.

      app/backend/tests

    Architecture

    Everything on your laptop, and what it provisions in AWS

    Moving lines show the direction of data. Choose a step above to isolate its part of the system.

    1. Terraform provisions the VPC, the EC2 host and the RDS instance.
    2. build-app.sh output (wheelhouse and React bundle) is copied to the host over SSH.
    3. AWX runs the Ansible job against the host over SSH.
    4. vault-main issues the TLS certificate and secrets. Ansible fetches them on the control node and copies them over as files.
    5. Vault's database engine mints one-hour Postgres credentials, reaching RDS through an SSH tunnel via the host.

    Hand-drawn from infra/docs/architecture.md, which holds the same picture as a Mermaid diagram and the reasoning behind each piece.

    Safety and limits

    What is real, what is simplified

    • The demo is simulated end to end. It makes no network calls and its credentials unlock nothing.
    • Vault's own listener runs without TLS in this lab. The app's TLS, issued by Vault PKI, is real.
    • The PKI root is self-signed, not an offline organisational root.
    • This is not a physically air-gapped network. It is a normal AWS account with one host's egress removed by security group.
    • One configured admin user, no roles. The JWT is kept in localStorage.
    • The AWS platform is documented in the repo but is not running behind this page; the demo above is a simulator, not a view of it.

    Honest fit

    Where it is not the right tool

    • A production HR system: no roles, no persisted audit trail, no SSO.
    • A large directory: the API caps a page at 1,000 rows and the UI does not paginate.
    • A template for a managed-cloud stack: it replaces cloud KMS, a registry and Git hosting with lab equivalents on purpose.
    • A Vault hardening guide: it shows the wiring, not a production configuration.
